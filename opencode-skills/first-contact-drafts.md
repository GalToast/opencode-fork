# First Contact Drafts (Opencode)

## Overview
Write short, personal first-contact drafts based on the single biggest verified issue.

## Workflow
1. Read repo memory and Good Neighbor policy.
2. Use only one biggest issue per draft (security, broken flows, site down, legal/compliance, or severe performance).
3. If the issue is mobile speed:
   - Mention around 50% of traffic is mobile.
   - Include the stat: 53% of mobile visitors leave if a page takes longer than 3 seconds.
4. Add a short parenthetical in the subject that clarifies the specific issue or reason for contact, e.g., "(couldn't find it)", "(missing security headers)", "(form not submitting)".
5. Include a gentle fielding line offering to share exact details so their team can fix it quickly.
6. Avoid "are you the right person" and avoid em dashes.
7. For parked or non-resolving domains, ask if they have a different preferred link.
8. Create the draft in Hostinger Mail and update queues/logs per repo conventions.

## Tone rules
- Warm, direct, real, and non-salesy.
- Short paragraphs, one clear observation, one ask.
- No jargon or AI-sounding phrasing.

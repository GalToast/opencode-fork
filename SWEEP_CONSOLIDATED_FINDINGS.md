### Bug #8 Detail: Child Tasks Killed on Parent Turn Completion

**Root cause:** `shouldCancelFromParentAbort()` in `task.ts` returned `true` whenever the parent's abort signal fired — including when the parent turn completed normally and the `defer(() => cancelTurn(...))` cleanup ran. This killed any still-running child tasks unnecessarily.

**Fix:** Added `SessionPrompt.hasActiveTurn(sessionID)` check. Now `shouldCancelFromParentAbort()` returns `false` (don't cancel children) when the parent has no active turns — meaning the parent completed normally and the abort is just cleanup. Only explicit user cancels or hard errors still kill children.

**New exports:** `startTurn`, `cancelTurn`, `hasActiveTurn` added to `SessionPrompt` namespace.
